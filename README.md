# History-Start Sensitivity in Retail Forecast Evaluation

Reproducibility repository for **“When Does History Start Matter? Model-Specific Sensitivity and Global Robustness in Retail Forecast Evaluation.”**

## Repository structure

- `notebooks/` — lightweight runner notebooks, numbered in execution order.
- `src/` — version-controlled experiment and post-processing logic used by the runners.
- `results/` — compact derived paper-facing summaries; no third-party raw data.
- `paper/` — modular LaTeX manuscript source and bibliography. Paper figures are regenerated by `04_final_analysis` using the filenames referenced by the manuscript.
- `DATA_SOURCES.md` — dataset provenance, access routes, license notes, and the FreshRetail metadata discrepancy noted during verification.
- `requirements.txt` — lightweight Python environment specification.

Keeping the substantive code in `src/` makes Git diffs readable while retaining notebooks as convenient Colab/Jupyter entry points.

## Data

Raw third-party datasets are **not included**. See [`DATA_SOURCES.md`](DATA_SOURCES.md).

### Visuelle 2.0

Obtain Visuelle 2.0 through the official project page and access form:
https://humaticslab.github.io/forecasting/visuelle

The public code intentionally does not embed or bypass the provider's access route. By default the main experiment expects the downloaded archive at:

`MyDrive/history_start_sensitivity/data/visuelle2.zip`

Alternatively, edit `VISUELLE_SOURCE` in `src/visuelle/part_01.py` to point to the downloaded archive, `sales.csv`, or a directory containing `sales.csv`.

### FreshRetailNet-50K

The FreshRetail workflow loads the official Dingdong-Inc release from Hugging Face:
https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K

The official dataset card lists version 1.0 and CC BY 4.0. See `DATA_SOURCES.md` for the exact columns used and provenance notes.

## Quick start

```bash
git clone https://github.com/hjy075/history-start-sensitivity.git
cd history-start-sensitivity
pip install -r requirements.txt
```

Run the workflows in this order:

1. `notebooks/01_visuelle_main.ipynb`
2. `notebooks/02_freshretail_data_gate.ipynb`
3. `notebooks/03_freshretail_main.ipynb`
4. `notebooks/04_final_analysis.ipynb`

The runner notebooks expect the repository directory structure to be preserved. In Google Colab, clone the repository first and run the notebook from the cloned `notebooks/` directory. Persistent caches and experiment outputs are stored under `MyDrive/history_start_sensitivity/` when Drive is mounted.

## Paper figures

`04_final_analysis` regenerates the six manuscript figures into its `paper_outputs/figures` directory using these filenames:

- `visuelle_local_effects.png`
- `freshretail_local_effects.png`
- `freshretail_target_day_profile.png`
- `local_rank_stability.png`
- `visuelle_metric_normalization.png`
- `freshretail_metric_normalization.png`

For a local LaTeX build, place/copy those generated images under `paper/figures/`. The arXiv submission package contains the static figures used for the submitted preprint.

## Environment

The forecasting experiments use `statsforecast==2.1.1`; final inference uses a 5,000-replicate product-cluster bootstrap targeting the series-weighted estimand. See `requirements.txt` for dependencies.
